## 2. Проект в цифрах

- Java 21 (собирается и на JDK 25), Spring Boot 3.5.14, Spring Security 6.5 (SAML 2.0 / Entra ID), JPA + Flyway
  (13 миграций), PostgreSQL, Spring LDAP (синхронизация с AD), Apache POI (Excel), Vanilla JS.
- `src/main/java`: ~155 файлов / ~12 200 строк; тесты Java: ~87 файлов / ~12 300 строк (соотношение ~1:1).
- Фронтенд: ~4 800 строк JS, ~4 300 строк CSS; JS-тесты ~2 200 строк (mini-DOM, без браузера).
- Источник сотрудников: `EMPLOYEE_SOURCE=db` (синхронизация из AD), откат — `excel`.
- Вход: SSO через Entra ID, у каждого своя учётная запись.

## 3. Тесты

Команда: `./mvnw test` (JS-тесты запускаются из `JsTestsTest`, нужен Node).

- 14 тестовых классов используют профиль `local`, то есть **реальную PostgreSQL** из `DB_HOST/DB_NAME`
  (по умолчанию dev-БД `OrgStructure`); остальные — профиль `test` (H2 in-memory).
- `FaqSeedParityTest` на dev-БД падает: он сверяет строки `function_faq` с `updated_by = 'migration'`, а FAQ функций
  ITS и QRM там правились через UI под `dev`. На чистой БД (как в CI) тест проходит.
- Рекомендация: тесты — на отдельной БД (`DB_NAME=orgchart_test`) или через Testcontainers.

## 4. Безопасность: исправлено

| # | Проблема | Риск | Исправление |
|---|---|---|---|
| 1 | `script-src 'unsafe-inline'` в CSP: любая внедрённая HTML-строка с `onclick=`/`<script>` выполнилась бы | Средний (вторая линия защиты от XSS) | Для всех страниц сайта `script-src 'self'`; `'unsafe-inline'` только для страниц, которые пишет Spring (`/login`, `/saml2/authenticate/entra` — POST binding). Вид «Groups» использовал два `onclick=` — переведены на делегированный обработчик. Проверено в Edge (Playwright): все страницы, профиль, группы, FAQ-редактор, админка, Swagger — без нарушений CSP и ошибок JS. `HardeningTest` проверяет заголовки и отсутствие инлайн-обработчиков в JS/HTML |
| 2 | Персональные данные в git: `data/result_new.xlsx` (205 сотрудников) и фото с e-mail в именах. **Репозиторий на GitHub публичный** | Высокий | Файлы убраны из индекса (на диске остались), `data/` и `photos/*` в `.gitignore` (кроме `default.jpg`). История — раздел 5.1 |
| 3 | `@CrossOrigin(origins = "*")` на 5 контроллерах | Средний при открытом сайте, низкий при SSO | Удалено, фронтенд работает с того же адреса |
| 4 | Apache POI 5.3.0 — CVE-2025-31672 | Средний | POI 5.4.1, commons-io 2.20.0 |
| 5 | springdoc 2.5.0 несовместим со Spring 6.2; Swagger открыт всем | Низкий | springdoc 2.8.9; выключен вне `local` (`SPRINGDOC_ENABLED`) |
| 6 | Лайки без `visitorId` обходили проверку дубликата | Низкий | `visitorId` обязателен, длины ≤ 255 |
| 7 | Подделка строк лога через значения запроса | Низкий | Переводы строк в сообщениях заменяются (`logback-spring.xml`) |
| 8 | docker-compose: PostgreSQL на `0.0.0.0:5432` с паролем `postgres` | Высокий при доступе из сети | Порт на `127.0.0.1`, пароль из `POSTGRES_PASSWORD` |
| 9 | CSP без `object-src`, `base-uri`, `frame-ancestors` | Низкий | Добавлены |
| 10 | Мёртвые правила: роль `HR_EDITOR` и правило для несуществующего `/api/admin/upload-excel`; роль `MONITORING_SYSTEM` для `/actuator/prometheus`, которую никто не получал | Низкий (лишняя поверхность) | Удалены роль, правило, `HR_EDITOR_EMAILS`, зависимость `micrometer-registry-prometheus`; Actuator отдаёт только `health` |

## 5. Требует решения / рекомендации

1. **История git.** Данные сотрудников есть во всех коммитах с 31.08.2026 и на GitHub (публичный репозиторий).
   Удаление из индекса закрывает только будущие коммиты. Нужно: сделать репозиторий приватным; вычистить историю
   (`git filter-repo --path data/result_new.xlsx --path-glob 'photos/*@*' --invert-paths`) и force-push всех веток;
   всем участникам заново клонировать репозиторий. Копии, которые уже скачаны или проиндексированы, вычистка не отзовёт.
2. **Аналитика** (`/api/page-visits`, `/api/interactions`, `/api/search-logs`, `/api/likes`) без лимита запросов.
   При SSO пишут только вошедшие сотрудники — риск низкий; при необходимости — rate limit на прокси.
3. **SSE `/api/org/stream`**: число подписчиков не ограничено, таймаут бесконечный.
4. **Пароль БД по умолчанию** `postgres` в `application.yaml` — лучше без значения по умолчанию в `prod`/`stage`.
5. **Логирование**: `cs_orgchart` на `DEBUG` во всех профилях, тексты поисковых запросов пишутся на `INFO`.

## 6. API

Публичные (всё, что видит сайт): `GET /api/functions`, `/api/employees[?cs=&country=]`, `/api/search?q=`,
`/api/functions/{cs}/faq`, `/api/people/{id}/external`, `/api/photos/{id}`, `/api/me/roles`, `/api/org/stream` (SSE),
`/api/likes/summary[/{email}]`; запись: `/api/likes`, `/api/page-visits`, `/api/interactions`, `/api/search-logs`,
`PUT/DELETE /api/me/photo`. Админские: `/api/manage/**` (`@adminAccess.isAdmin`), `/api/manage/admins` и
`/api/admin/**` (super admin).

Проверено тестами, чтением кода и на запущенном приложении:

- все `/api/manage/**` закрыты `@PreAuthorize`, это сверяет `AuthorizationMatrixTest`;
- все записи требуют CSRF-токен; `/api/**` без сессии — 401 JSON;
- `/api/me/photo` определяет человека только по сессии;
- загрузка фото: лимит размера до чтения, magic bytes и размеры до декодирования, перекодирование в чистый JPEG;
- SQL параметризованный, LDAP-фильтры экранируются;
- фронтенд: `innerHTML`-синки получают значения через `escapeHtml` (`StoredXssTest`), инлайн-скриптов нет (CSP);
- живая проверка: публичные GET — 200 за 10–110 мс; `/api/manage/**` без входа — 401; `/actuator/env` закрыт;
  `/photos/../pom.xml` — 400; POST без CSRF — 403; лайк без `visitorId` — 400; CORS-заголовков нет.

Замечания по дизайну (не ошибки): в аналитике тела — `Map<String, String>` вместо DTO; `GET /api/likes/summary`
отдаёт агрегаты по всем «лайкнутым» строкам; `addLike` возвращает сущность целиком.
